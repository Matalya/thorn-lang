Dictionaries

Dictionaries are mutable, insertion-ordered collections of key-value pairs. Their type is dict(K, V), where K is the key type and V is the value type. Dictionary literals use -> between each key and value and semicolons between entries; the final semicolon is optional.

The runic type alias is ᛞᛁᚳᛏ. Dictionary method aliases are ᛚᛖᛝᚦ, ᚷᛖᛏ, ᚻᚫᛋ, ᚱᛁᛗᚣᚠ, ᚳᛁᛁᛋ, ᚠᚫᛚᛄᚣᛋ, ᛠᛏᛖᛗᛋ, ᚳᛚᛁᚢᚱ, and ᚳᚪᛈᛁ for length, get, has, remove, keys, values, items, clear, and copy, respectively.

dict(str | int, int) scores = {
    "Ada" -> 10;
    "Grace" -> 20;
    3 -> 30
};

print(scores["Ada"]); # 10
scores["Linus"] = 40; # creates a new entry
scores["Ada"] += 5;   # updates an existing entry

Direct indexing with a missing key is a runtime error. get() provides nullable or default-backed access. Dictionaries cannot be sliced. foreach (key in dictionary) iterates keys in insertion order, and index(key) reports the key's insertion index within that iteration.

Keys must be hashable. Supported statically known key types are int, float, str, char, bool, nil, enum types, and pyobject; unions of hashable types are also supported. any in key position means any value that is hashable at runtime, not literally every Futhorc value. Lists, arrays, sets, dictionaries, files, and structs are not valid keys. A pyobject key is accepted only when its wrapped Python value is hashable.

Futhorc keeps key types distinct: true, 1, and 1.0 may coexist as three different keys. Dictionary equality compares key-value contents and does not depend on insertion order. Reassigning an existing key does not move it to the end.

An empty dictionary may be written as {} when its declared variable type is a concrete dict(K, V). The constructor dict(K, V) is unambiguous in every expression context and also creates an empty dictionary.

Heterogeneous arrays

Heterogeneous arrays are fixed positional schemas: compact, unnamed structs whose fields are addressed by index. Every slot has its own declared type.

arr(int, str, bool) data = <10, "hello">;

int number = data[0];
str greeting = data[1];
data[2] = true;

The schema above has capacity 3, inferred from its three type entries. Initializers may occupy any prefix of the schema, including the empty prefix. Unoccupied slots retain their declared types but cannot be read until initialized. Assigning at length() initializes the next slot; assigning beyond it is an error because heterogeneous arrays cannot contain gaps.

A type followed by * and a positive integer declares several consecutive slots of that type. Primitive, collection, enum, and struct types are all accepted:

arr(Person * 2, int, str * 3) record;

This expands to two Person slots, one int slot, and three str slots. Its capacity is inferred as 6. An explicit final capacity is optional, but when supplied it must equal the expanded schema exactly:

arr(Person * 2, int, str * 3, 6) valid;
arr(Person * 2, int, str * 3, 5) invalid; # schema/capacity error

An uncounted type contributes exactly one slot. Counts must be positive. The type * count syntax is contextual to an array type, so names such as Person3 remain ordinary, unambiguous type names.

A constant non-negative index has its precise positional type. A runtime-computed or negative index has the union of all types in the schema and is checked against the selected slot at runtime. Heterogeneous array schemas are part of static type identity: arr(int, str) and arr(str, int) are different types.

Operations that shift slots or alter capacity would invalidate the schema. Consequently, heterogeneous arrays support length, capacity, append, replace_at, shorten, search methods, locate, copy, and join when every slot is textual. They do not support resize, insert, prepend, remove_at, shave, compress, fill, skintight, or shrink_to_fit. Slicing is supported when its bounds are constant non-negative integers and produces the corresponding sliced schema.

Structs

Structs are named custom types that bundle an assortment of declared variable fields with their own types. A struct can hold data of any type. The basic structure is: ``` struct StructType { type field_name; type field_name = default_value;

type func(StructType self, type arg) { # func body } }

Example:

Declaration and instantiation

struct Person { str name; int age; str citizen; int height; float weight; list(str) interests;

nil grow_up(Person self, int years) {
  self.age += years;
}

Person whoIsOlder(Person a, Person b) {
  if (a.age > b.age) {
    return a;
  } else {
    return b;
  }
}

}

Person Lucas = {
    name = "Lucas";
    age = 17;
    citizen = "Argentine";
    height = 175;
    weight = 82.9;
    interests = ["rock", "pc gaming", "football", "girls"];
}

in-line

func(Person {name = "Lucas"; ...}) Notice how the named type for the aggregated data isn't one of the contained field types but a custom-named one. This integration with the type checker is the biggest advantage structs offer.

A few ground rules to keep in consideration:
  • Methods are implemented as syntax sugar over free functions. Lucas.grow_up(5) gets resolved to Person::grow_up(Lucas, 5).
  • An instance method is any function whose first parameter is StructType self; the StructType is mandatory for consistency with the rest of the language, but self is a reserved keyword. Otherwise, the function is considered a static method. For example, whoIsOlder(Person a, Person b) would be callable only as Person.whoIsOlder(Lucas, Marcos) instead of Lucas.whoIsOlder(Lucas, Marcos).
  • A bare self parameter is invalid. Writing nil restock(self, int amount) {} produces a specific missing-type error suggesting the required form, such as nil restock(Product self, int amount) {}.
  • Uninitialized fields with no default raises an error.
  • Re-initializing fields (for example, if you defined age twice) raise an error
  • Initializing fields not present in the definition raises an error.
  • Struct literals behave as expressions and evaluate to the newly created object without requiring it to be bound to a variable.

Printing

Printing a struct instance, interpolating it into a composite string, or converting it with str() uses a field-oriented representation: StructType { fieldName = value, otherField = value }

Fields are printed in their declaration order. Values use their normal Futhorc display form recursively, so nested collections and structs are displayed within the containing struct. Strings are displayed without surrounding quotes.


struct Product {
    str name;
    float price;
    int stock;
}
Product coffee = Product.new("Coffee", 4.5, 3);
print(coffee);

Product { name = Coffee, price = 4.5, stock = 3 }

Default, constant and mandatory fields

enum Clearance = (

    LEVEL_FOUR;

    str name;

The ID cannot be changed because it's a security measure, so it's assigned as a constant. This constant, in turn, is initialized upon instanciation. Clearance level is assumed to be the lowest possible unless stated otherwise. Finally, all employees must carry the employee manual, so it is assigned automatically and cannot be reassigned.

Built-in functions and equality

All structs come with several important functions that enable certain functionalities. - StructType StructType.new(*args): creates a new instance of the struct - StructType structInstance.copy(): creates a deep copy of the struct's instance - bool structInstanceA.resembles(structInstanceB): makes a deep comparison of the contents of A and B.

Enumerations

Enumerations (Abbreviated as enums) are a closed collection of discrete data instances related by their custom named type. enum(int) Directions = ( UP = 0; DOWN = 1; LEFT = 2; RIGHT = 3; ) All of them have a unified type of int so they don't need to have it specified inline.

Enums support auto-incremented values. To do this, you have to not define a value on all fields, and they'll be initialized with + 1 from the previous one. By default the first field will start at 0, but you can define the initial value instead. Enums are always constants and cannot be reassigned, even with the new keyword. 

enum(int) Positions = (
    FIRST = 1;
    SECOND; #2
    THIRD; #3
    FOURTH; #4
    FIFTH; #5
)
enum(int) Weather = (
    SUNNY; #0
    RAINY; #1
    STORMY; #2
)
enum(str) Color = (
    YELLOW = "yellow";
    BLACK = "black";
    GREEN = "green";
    RED = "red";
    BLUE = "blue"
)
In a similar vein, enums create a custom type whose valid values can be checked up against the known valid values specified at the enum definition. This way: Weather CLOUDY = 3; will result in an error, becaus even though it's an int as specified, it's an invalid value for the Weather type.

Scope

Futhorc uses function-level lexical scope. Function bodies create local scopes; control-flow bodies do not. Variables declared within control-flow bodies are added to the nearest containing function scope, or to the global scope when no function contains them. Their initialization remains conditional on whether execution reaches the declaration.

any

any is close to TypeScript's unknown. In practice, a function with a return type of any can only be assigned to variables with a type of any, but any can take on any type. However, performing operations on an any-tagged variable requires you to narrow it down via conversion or type-checking using is_* functions.

File handling

Futhorc provides Python-backed text file handling through the built-in File type. Python's mature text I/O implementation supplies buffering, newline conversion, character encoding, seeking, and operating-system integration, while Futhorc supplies static types and source-positioned runtime diagnostics.

Files are opened with open(). Relative paths are resolved from the process working directory; absolute paths are used directly. The default encoding is UTF-8.

Printing a File, interpolating it into a composite string, or converting it with str() displays its supplied path, mode, and closed state:

File { path = examples/notes.txt, mode = r, closed = false }

Supported text modes are: - "r": read an existing file. - "w": write a file, truncating existing contents. - "a": append to the end of a file. - "x": create a new file and fail if it already exists. - "r+", "w+", and "a+": corresponding modes that permit both reading and writing.

Binary modes such as "rb" and "wb" are not supported because Futhorc does not yet have a bytes type.

Files should be closed explicitly with close() when no longer needed. The interpreter also closes every remaining open file when program execution ends, including when execution ends because of a runtime error.

tell() returns an opaque text-stream position. In particular, it is not guaranteed to equal a character count or UTF-8 byte count. A position returned by tell() can safely be passed back to seek().

Opening failures, permission errors, invalid operations, encoding failures, and operations on closed files produce Futhorc runtime errors. File contents are not automatically serialized into Futhorc values; programs read and write strings and lists of strings explicitly.

Native modules

Each .futhorc or .þ source file is a module. Native imports preserve Futhorc's static types across file boundaries:

import tools;
import tools as t;
from tools import helper;
from tools import helper as h;

import tools; binds the module object as the constant tools. import tools as t; chooses another binding name. A from import binds one exported value or type directly; as can rename it. Imported variables, functions, structs, and enums retain their declared types, so calls, assignments, member access, and nominal struct identity are still checked statically.

Module names are single identifiers and resolve to files directly inside the entry source file's directory. For example, import people; searches for people.þ and people.futhorc. It is an error when neither candidate exists or when both exist. Dots retain their ordinary member-access meaning and are not translated into filesystem separators; use from world import people; to import the exported member people from module world. Native imports require execution from a source file because an in-memory source string without a path has no module root.

Every top-level variable, function, struct, enum, enum member, or imported binding is exported. Module objects expose exported values and functions through member access, such as tools.answer or tools.calculate(). Import types directly with from tools import Result; before using them in declarations or constructors.

A module has its own global environment and is initialized on its first executed import. The initialized module is cached, so importing it again does not rerun its top-level statements. from imports capture the exported value when the import statement executes, while member access reads through the module environment. Circular imports are rejected with the import chain in the diagnostic.

The runic aliases are ᛁᛗᛈᛟᚱᛏ, ᚠᚱᛟᛗ, and ᚫᛋ for import, from, and as respectively.

Python interoperability

Futhorc can access modules from the Python environment running the interpreter. Python interoperability is an explicitly dynamic boundary: ordinary Futhorc remains statically typed, while foreign modules, callables, attributes, and results use the pyobject type.

Runic aliases are ßøêßøáßÜ¬ßøÆßÜÀßÜ╗ßøûßÜ│ßøÅ for pyobject, ßøêßøáßøüßøùßøêßøƒßÜ▒ßøÅ for pyimport, and ßøùßÜ½ßÜÀßÜ╗ßÜúßøÜ for its module parameter. The native import-statement aliases are ßøüßøùßøêßøƒßÜ▒ßøÅ, ßøêßøáßÜªßÜúßÜ¥, and ßÜ½ßøï for import, python, and as respectively.

Python modules can be imported with a native statement: import python "math" as math; This is syntactic sugar for a statically typed pyobject declaration initialized through pyimport(): pyobject math = pyimport("math"); The module name must be a string literal and as must provide a normal Futhorc identifier. The binding follows ordinary Futhorc declaration and function-level scope rules. Importing a missing module produces the same source-positioned runtime error as pyimport().

pyimport() uses Python's normal module discovery rules and therefore sees the standard library and packages installed in the active Python environment. A pyobject supports dynamic member access, calls with positional or named arguments, indexing, slicing, and iteration through foreach. Each such operation has static result type pyobject; programs use explicit Futhorc conversions such as int(), float(), str(), bool(), or to_list() when they need an ordinary Futhorc value.

Futhorc primitives cross into Python as their corresponding Python primitives. Lists and arrays cross as copied Python lists, sets cross as copied Python tuples, dictionaries cross as copied Python dictionaries, and enums cross as their backing values. Mutating a copied collection in Python does not mutate the original Futhorc collection. If distinct Futhorc keys would collide under Python equality, such as true and 1, conversion raises a runtime error rather than silently losing an entry. Struct conversion and callbacks from Python into Futhorc functions are not yet defined.

Python exceptions are converted into source-positioned Futhorc runtime errors containing the Python exception class and message. Python interoperability is not sandboxed: imported modules have the same filesystem, network, process, and native-extension privileges as the interpreter.

Built-ins:

* This documentation uses ?value to mean "optional parameter". However, this is merely notational and is not valid Futhorc source. Parameters become optional by providing a default evaluation with =.

In collection method signatures, T represents the collection's element type. In array signatures, N represents runtime capacity. Array capacity is not part of static type identity: arr(T, 3) and arr(T, 8) have the same static type.

Collection indexes are zero-based. Negative indexes count backwards from the end of the collection:

collection[-n] == collection[collection.length() - n]

For example, collection[-1] accesses the last item and collection[-2] accesses the second-to-last item. An index outside the occupied range is a runtime error.

For methods that insert at an index, index == length() is valid and inserts at the end. An index greater than the collection's length is an error; insertion never creates gaps filled with nil.

Search methods return nil when no matching item or occurrence exists. find_nth(item, number) uses one-based occurrence numbering: 1 means the first occurrence, 2 the second, and so on. A number below 1 is a runtime error.

copy() performs a deep copy. Nested collections and structs are recursively copied. Repeated references and cycles preserve their topology: if two references in the original point to the same object, their copies point to the same copied object rather than two independent copies.

  • Invocation syntax is arr(T, value, capacity). value and capacity may also be named, so arr(T, capacity = N) creates an empty array with reserved capacity.

  • Invocation syntax is set(T, value) or set(T).
  • dict(K, V) dict(type K, type V, any ?value)
  • Creates a dictionary whose keys have type K and values have type V.
  • Returns an empty dictionary if value is omitted.
  • Copies entries from another Futhorc dictionary or from a Python mapping held by pyobject.
  • The returned dictionary is a fresh outer collection; later mutation does not affect the source.
  • Every key and value must already match its declared type. Keys must additionally be hashable.

These conversions always create a fresh outer collection and never mutate the source. A Futhorc collection, string, or foreign Python iterable is copied in iteration order; a non-iterable Futhorc value becomes one element. Elements are not individually coerced through primitive conversion functions: every produced element must already be compatible with T, otherwise conversion raises a source-positioned runtime error. Nested collection elements are checked recursively. Contained object identities are retained, so this is an outer-container copy rather than copy()'s recursive deep copy.

  • When characters is provided, removes any of those characters from both ends.
  • list(str) split(str separator = whitespace)
  • Splits on runs of whitespace when separator is omitted.
  • When separator is provided, splits on that exact substring.
  • str replace(str old, str replacement, int count = -1)
  • Replaces non-overlapping occurrences of old from left to right.
  • A negative count replaces every occurrence.
  • bool contains(str substring)
  • Returns whether substring occurs in the string.
  • bool starts_with(str prefix)
  • Returns whether the string begins with prefix.
  • bool ends_with(str suffix)
  • Returns whether the string ends with suffix.
  • int | nil find(str substring)
  • Returns the zero-based index of the first occurrence of substring, or nil when it is absent.
  • int count(str substring)
  • Returns the number of non-overlapping occurrences of substring.

  • nil append(T item)

  • Returns the removed item.
  • list(T) shave(int amount = 1)

  • int length()
  • Returns the number of items in the list.
  • int | nil find_first(any item)

  • Returns nil if no occurrence exists.

  • Returns the index of the last occurrence of item.

Array methods

Arrays have both a length and a capacity.

str join(str separator = "") is available only on textual arrays and performs no implicit stringification.

  • length is the number of occupied elements.
  • capacity is the number of elements the array can contain before explicit resizing is required.
  • For homogeneous arr(T, N), capacity is runtime allocation and is not part of static type identity. For heterogeneous arrays, capacity is fixed by the positional schema and the complete schema is part of static type identity.
  • Unoccupied capacity consists of internal empty slots. Empty slots are not Futhorc nil values and cannot be accessed as elements.
  • Arrays never resize automatically. Operations that would exceed capacity produce a runtime error. Homogeneous capacity may be increased explicitly; heterogeneous capacity cannot be changed because every position has a declared type.
  • Capacity changes are visible through every alias referring to the same array.
  • Assigning an existing array to a declaration written with a different N does not resize it.

Methods that access, replace, or remove existing items require an occupied index. An index below the array's capacity may still be invalid when it refers to an empty slot.

  • nil resize(int new_size)
  • Explicitly changes the array's capacity.
  • new_size < 0 is an error.
  • new_size == capacity() does nothing.
  • Increasing capacity creates additional internal empty slots and does not change length.
  • Reducing capacity below the current length truncates elements from the end until length() <= new_size and emits a runtime warning.
  • Resizing to 0 is valid; any occupied elements are truncated with a warning.
  • int length()
  • Returns the number of occupied elements in the array.
  • int capacity()
  • Returns the current runtime capacity of the array.
  • nil append(T item)
  • Adds item to the end of the occupied portion of the array.
  • Raises an error if the array is full.
  • On a heterogeneous array, item must match the next slot's declared type.
  • nil insert(T item, int index)
  • Adds item at index and shifts the item previously at that index and all following occupied items one position forward.
  • index == length() inserts at the end.
  • Raises an error if the array is full.
  • An index greater than the current length is an error.
  • nil prepend(T item)
  • Adds item to the beginning of the array and shifts all occupied items one position forward.
  • Raises an error if the array is full.
  • T replace_at(T item, int index)
  • Replaces the occupied item at index with item.
  • Returns the previous item.
  • Does not change length or capacity.
  • On a heterogeneous array, item must match the selected slot's declared type.
  • list(T) shorten(int amount = 1)
  • Removes amount occupied items from the end of the array.
  • Returns the removed items as a list in their original order.
  • Does not change array capacity.
  • T remove_at(int index)
  • Removes the occupied item at index, shifts all following occupied items one position backward, and leaves an empty slot at the end of the occupied portion.
  • Returns the removed item.
  • Does not change capacity.
  • list(T) shave(int amount = 1)
  • Removes amount occupied items from the beginning of the array.
  • Shifts the remaining occupied items backward and returns the removed items as a list in their original order.
  • Does not change array capacity.
  • int | nil find_first(any item)
  • Returns the index of the first occurrence of item.
  • Returns nil if no occurrence exists.
  • int | nil find_nth(any item, int number)
  • Returns the index of the specified occurrence of item.
  • number is one-based.
  • Returns nil if that occurrence does not exist.
  • A number below 1 is an error.
  • int | nil find_last(any item)
  • Returns the index of the last occurrence of item.
  • Returns nil if no occurrence exists.
  • T locate(int index)
  • Returns the occupied item at index.
  • Negative indexes count backwards from the end of the occupied elements, not from capacity.
  • nil compress()
  • Removes all actual nil values from the occupied portion of the array and shifts the remaining elements together while preserving their order.
  • Capacity remains unchanged.
  • Internal empty slots are not Futhorc nil and are unaffected.
  • On an array whose element type cannot contain nil, this is normally a no-op. <1, 2, 3, nil, 4, nil, 5> Ôåô <1, 2, 3, 4, 5>
  • arr(T, N) copy()
  • Returns a deep copy of the array.
  • The copied array initially has the same current capacity as the source array.

  • Fills every currently unoccupied slot with value.

Slicing a homogeneous array produces a new array containing the selected occupied elements with capacity equal to its resulting length. Heterogeneous array slices require constant non-negative bounds and retain the corresponding portion of the positional schema, including unoccupied typed slots.

Set methods

Futhorc sets are ordered, immutable collections. Unlike mathematical sets and sets in many other languages, Futhorc sets permit duplicate values and retain their order. Their contents cannot be added to, removed from, replaced, or reordered after construction.

str join(str separator = "") is available only on textual sets and performs no implicit stringification.

A non-const variable containing a set may still be rebound to another set. const set(T) prevents that rebinding as well.

  • int length()
  • Returns the number of items in the set.
  • int | nil find_first(any item)
  • Returns the index of the first occurrence of item.
  • Returns nil if no occurrence exists.
  • int | nil find_nth(any item, int number)
  • Returns the index of the specified occurrence of item.
  • number is one-based.
  • Returns nil if that occurrence does not exist.
  • A number below 1 is an error.
  • int | nil find_last(any item)
  • Returns the index of the last occurrence of item.
  • Returns nil if no occurrence exists.
  • T locate(int index)
  • Returns the item at index.
  • Negative indexes count backwards from the end.
  • set(T) copy()
  • Returns a deep copy of the set.

File handling

  • File open(str path, str mode = "r", str encoding = "utf-8")
  • Opens a text file. Supported modes are r, w, a, x, and their + variants.
  • Binary modes are unavailable until Futhorc has a bytes type.
  • str File.read(int | nil size = nil)
  • Reads the rest of the file, or at most size characters when supplied.
  • str File.readline(int | nil size = nil)
  • Reads one line, optionally limited to size characters. A retained line terminator is part of the returned string.
  • list(str) File.readlines()
  • Reads all remaining lines, retaining their line terminators.
  • int File.write(str content)
  • Writes content at the current position and returns the number of characters accepted.
  • nil File.writelines(list(str) lines)
  • Writes each string exactly as supplied. Newline characters are not added automatically.
  • nil File.flush()
  • Flushes buffered output to the underlying stream.
  • int File.seek(int offset, int origin = 0)
  • Moves the stream position. origin uses Python-compatible values: 0 for the beginning, 1 for the current position, and 2 for the end, subject to text-stream restrictions.
  • int File.tell()
  • Returns an opaque text-stream position suitable for passing back to seek().
  • nil File.close()
  • Flushes and closes the file. Calling close() on an already closed file does nothing.
  • bool File.closed()
  • Returns whether the file is closed.
  • bool File.readable()
  • Returns whether the selected mode permits reading.
  • bool File.writable()
  • Returns whether the selected mode permits writing.
  • bool File.seekable()
  • Returns whether the underlying stream supports seeking.

File and encoding failures are reported as source-positioned Futhorc runtime errors.

Python interoperability

  • pyobject pyimport(str module)
  • Imports module using Python's normal import system and returns the module as a foreign object.
  • Runic form: pyobject pyimport(str module).
  • import python "module" as binding;
  • Imports the Python module and declares binding with static type pyobject.
  • Equivalent to pyobject binding = pyimport("module");.

Operations supported by pyobject values: - object.member: dynamically retrieves a Python attribute and returns it as pyobject. - object(arguments...): invokes a wrapped Python callable. Futhorc named arguments become Python keyword arguments. - object[index]: performs Python indexing and returns pyobject. - object[start:end]: performs Python slicing and returns pyobject. - foreach (item in object): iterates a Python iterable; each item has static type pyobject.

Python return values remain pyobject even when their runtime value is a Python primitive. Explicit Futhorc conversion establishes a statically known Futhorc type.
