## Boolean operations and truthiness:
Truthiness can only be accessed with the built-in `bool()` function, that gets any data as its argument and returns its truthy value. Truthiness can otherwise not be accessed, and instead explicit boolean values must be used in logical operations.
- **Comparisons** like `==`, `<` and `>=` can take numeric values (`int`, `float`), as well as boolean values `true` and `false`.
- **Logic operators** like `and`, `or` and `xor` can only be performed on strict boolean values, or type-casted non-boolean values through the `bool()` function.
  - `5 and false` ❌
  - `bool(5) and false` ✅


## Collections:
- list: `list(type)` [1, 2, 3] (mutable, dynamically resizable)
- array: `arr(t, n)` <1, 2, 3> (mutable, non-dynamically resizable)

- *mutable: can the items of the collection be changed/added upon?*
- *resizable: can the collection be dynamically resized with each insertion and deletion?\**
- *rebindable: can the variable be reassigned to something else?*
```
           |mutable|resizable|rebindable

arr        |   ✅  |   ❌   |   ✅

```
\* arrays are not dynamically resizable, but they can be resized with the methods listed further down. The capacity is runtime allocation.
\* Thorn sets are immutable, ordered collections that permit duplicate elements; they behave like immutable lists rather than mathematical sets.

## Typed arrays
Typed arrays are arrays that can store multiple types of data in an ordered manner. Their minimum length is determined by the amount of types specified. A typed array is, syntactically, an array whose type passed is a list of types.

### Unnumbered types
`arr([int, str, float], 3)`: this type can hold 3 items, and the order in which they're held must match that of their definition. As such, `[1, "a", 1.5]` is a valid form, but `["a", 1, 1.0]` isn't.

However, if we change it to `arr([] int, str, float, 4)`, now you'll see that there are more items than there are types. This allows you to put more than one, as long as the order is preserved and all types are covered. As such, all of the following are valid
```
[1, "a", 1.0]
[1, 2, "a", 1.0]
[1, "a", "b", 1.0]
[1, "a", 1.0, 2.0]
```
### Numbered types

No number next to the type means "any amount". However, a number means "this exact amount, no more, no less". For example: `arr([str, int3], 10)` represents an array that contains between 1 and 7 strings, and exactly 3 integers, and `arr([str1, int3], 4)` *has* to contain one string and 3 integers. This is similar to Rust's tuple structs. It goes without saying that, if the length of the array doesn't match the amount expressed in the types, the program will error. However, it can be left empty and the interpreter will automatically pre-compute the correct minimal amount, which for numbered type arrays, is in fact the recommended approach to keep typoes and confusions from causing errors.

## Structs
Structs are named custom types that bundle an assortment of declared variable fields with their own types. A `struct` can hold data of any type. The basic structure is:
```
struct StructType {
  type field_name;
  type field_name = default_value;

  type func(StructType self, type arg) {
    # func body
  }
}
```

Example:

### Declaration and instantiation
```
struct Person {
    str name;
    int age;
    str citizen;
    int height;
    float weight;
    list(str) interests;

    nil grow_up(Person self, int years) {
      self.age += years;
    }

    Person whoIsOlder(Person a, Person b) {
      if (a.age > b.age) {
        return a;
      } else {
        return b;
      }
    }
}

Person Lucas = {
    name = "Lucas";
    age = 17;
    citizen = "Argentine";
    height = 175;
    weight = 82.9;
    interests = ["rock", "pc gaming", "football", "girls"];
}

# in-line
func(Person {name = "Lucas"; ...})
```
Notice how the named type for the aggregated data isn't one of the contained field types but a custom-named one. This integration with the type checker is the biggest advantage structs offer.

A few ground rules to keep in consideration:
- Methods are implemented as syntax sugar over free functions. `Lucas.grow_up(5)` gets resolved to `Person::grow_up(Lucas, 5)`.
- An instance method is any function whose first parameter is `StructType self`; the StructType is mandatory for consistency with the rest of the language, but `self` is a reserved keyword. Otherwise, the function is considered a static method. For example, `whoIsOlder(Person a, Person b)` would be callable only as `Person.whoIsOlder(Lucas, Marcos)` instead of `Lucas.whoIsOlder(Lucas, Marcos)`.
- A bare `self` parameter is invalid. Writing `nil restock(self, int amount) {}` produces a specific missing-type error suggesting the required form, such as `nil restock(Product self, int amount) {}`.
- Uninitialized fields with no default raises an error.
- Re-initializing fields (for example, if you defined `age` twice) raise an error
- Initializing fields not present in the definition raises an error.
- Struct literals behave as expressions and evaluate to the newly created object without requiring it to be bound to a variable.
### Accessing
```
print(Lucas.age)
print(Lucas.interests[1])
>> 17
pc gaming
```
## Printing
Printing a struct instance, interpolating it into a composite string, or converting it with `str()` uses a field-oriented representation:
```
StructType { fieldName = value, otherField = value }
```

Fields are printed in their declaration order. Values use their normal Thorn display form recursively, so nested collections and structs are displayed within the containing struct. Strings are displayed without surrounding quotes.

```
struct Product {
    str name;
    float price;
    int stock;
}

Product coffee = Product.new("Coffee", 4.5, 3);
print(coffee);

>> Product { name = Coffee, price = 4.5, stock = 3 }
```
### Default, constant and mandatory fields
```
enum Clearance = (
    LEVEL_ONE;
    LEVEL_TWO;
    LEVEL_THREE;
    LEVEL_FOUR;
    MAXIMUM_LEVEL;
)
struct Employee {
    str name;
    const int id;
    Clearance clearance = LEVEL_ONE;
    const str manual = EMPLOYEE_MANUAL;
}
Employee johnSmith = {
    name = "John Smith";
    id = 25684978
}
```

The ID cannot be changed because it's a security measure, so it's assigned as a constant. This constant, in turn, is initialized upon instanciation. Clearance level is assumed to be the lowest possible unless stated otherwise. Finally, all employees must carry the employee manual, so it is assigned automatically and cannot be reassigned.
## Built-in functions and equality
All structs come with several important functions that enable certain functionalities. 
- `StructType StructType.new(*args)`: creates a new instance of the struct
- `StructType structInstance.copy()`: creates a deep copy of the struct's instance
- `bool structInstanceA.resembles(structInstanceB)`: makes a deep comparison of the contents of A and B.
```
struct Sample {
  int sample;
}

Sample a = Sample.new(1)
Sample b = a
Sample c = a.copy()

print(a == b)         # true
print(a == c)         # false
print(a.resembles(c)) # true
```
- Equality of structs is based on memory identity (Like Python's `is` keyword).

## Enumerations
Enumerations (Abbreviated as enums) are a closed collection of discrete data instances related by their custom named type.
```
enum(int) Directions = (
    UP = 0;
    DOWN = 1;
    LEFT = 2;
    RIGHT = 3;
)
```
All of them have a unified type of int so they don't need to have it specified inline.

Enums support auto-incremented values. To do this, you have to not define a value on all fields, and they'll be initialized with + 1 from the previous one. By default the first field will start at 0, but you can define the initial value instead. Enums are always constants and cannot be reassigned, even with the `new` keyword.
```
enum(int) Positions = (
    FIRST = 1;
    SECOND; #2
    THIRD; #3
    FOURTH; #4
    FIFTH; #5
)

enum(int) Weather = (
    SUNNY; #0
    RAINY; #1
    STORMY; #2
)

enum(str) Color = (
    YELLOW = "yellow";
    BLACK = "black";
    GREEN = "green";
    RED = "red";
    BLUE = "blue"
)
```
In a similar vein, enums create a custom type whose valid values can be checked up against the known valid values specified at the enum definition. This way: `Weather CLOUDY = 3;` will result in an error, becaus even though it's an int as specified, it's an invalid value for the `Weather` type.

## Scope
Thorn uses function-level lexical scope. Function bodies create local scopes; control-flow bodies do not. Variables declared within control-flow bodies are added to the nearest containing function scope, or to the global scope when no function contains them. Their initialization remains conditional on whether execution reaches the declaration.
## `any`
`any` is close to TypeScript's `unknown`. In practice, a function with a return type of `any` can only be assigned to variables with a type of `any`, but `any` can take on any type. However, performing operations on an `any`-tagged variable requires you to narrow it down via conversion or type-checking using `is_*` functions.

# File handling
Thorn provides Python-backed text file handling through the built-in `File` type. Python's mature text I/O implementation supplies buffering, newline conversion, character encoding, seeking, and operating-system integration, while Thorn supplies static types and source-positioned runtime diagnostics.

Files are opened with `open()`. Relative paths are resolved from the process working directory; absolute paths are used directly. The default encoding is UTF-8.

Supported text modes are:
- `"r"`: read an existing file.
- `"w"`: write a file, truncating existing contents.
- `"a"`: append to the end of a file.
- `"x"`: create a new file and fail if it already exists.
- `"r+"`, `"w+"`, and `"a+"`: corresponding modes that permit both reading and writing.

Binary modes such as `"rb"` and `"wb"` are not supported because Thorn does not yet have a `bytes` type.

Files should be closed explicitly with `close()` when no longer needed. The interpreter also closes every remaining open file when program execution ends, including when execution ends because of a runtime error.

`tell()` returns an opaque text-stream position. In particular, it is not guaranteed to equal a character count or UTF-8 byte count. A position returned by `tell()` can safely be passed back to `seek()`.

Opening failures, permission errors, invalid operations, encoding failures, and operations on closed files produce Thorn runtime errors. File contents are not automatically serialized into Thorn values; programs read and write strings and lists of strings explicitly.

# Python interoperability
Thorn can access modules from the Python environment running the interpreter. Python interoperability is an explicitly dynamic boundary: ordinary Thorn remains statically typed, while foreign modules, callables, attributes, and results use the `pyobject` type.

Runic aliases are `ᛈᛠᚪᛒᚷᚻᛖᚳᛏ` for `pyobject`, `ᛈᛠᛁᛗᛈᛟᚱᛏ` for `pyimport`, and `ᛗᚫᚷᚻᚣᛚ` for its `module` parameter. The native import-statement aliases are `ᛁᛗᛈᛟᚱᛏ`, `ᛈᛠᚦᚣᚾ`, and `ᚫᛋ` for `import`, `python`, and `as` respectively.

Python modules can be imported with a native statement:
```
import python "math" as math;
```
This is syntactic sugar for a statically typed `pyobject` declaration initialized through `pyimport()`:
```
pyobject math = pyimport("math");
```
The module name must be a string literal and `as` must provide a normal Thorn identifier. The binding follows ordinary Thorn declaration and function-level scope rules. Importing a missing module produces the same source-positioned runtime error as `pyimport()`.

`pyimport()` uses Python's normal module discovery rules and therefore sees the standard library and packages installed in the active Python environment. A `pyobject` supports dynamic member access, calls with positional or named arguments, indexing, slicing, and iteration through `foreach`. Each such operation has static result type `pyobject`; programs use explicit Thorn conversions such as `int()`, `float()`, `str()`, `bool()`, or `to_list()` when they need an ordinary Thorn value.

Thorn primitives cross into Python as their corresponding Python primitives. Lists and arrays cross as copied Python lists, sets cross as copied Python tuples, and enums cross as their backing values. Mutating a copied collection in Python does not mutate the original Thorn collection. Struct conversion and callbacks from Python into Thorn functions are not yet defined.

Python exceptions are converted into source-positioned Thorn runtime errors containing the Python exception class and message. Python interoperability is not sandboxed: imported modules have the same filesystem, network, process, and native-extension privileges as the interpreter.

# Built-ins:
\* This documentation uses `?value` to mean "optional parameter". However, this is merely notational and is not valid Thorn source. Parameters become optional by providing a default evaluation with `=`.

In collection method signatures, `T` represents the collection's element type. In array signatures, `N` represents runtime capacity. Array capacity is not part of static type identity: `arr(T, 3)` and `arr(T, 8)` have the same static type.

Collection indexes are zero-based. Negative indexes count backwards from the end of the collection:

```
collection[-n] == collection[collection.length() - n]
```

For example, `collection[-1]` accesses the last item and `collection[-2]` accesses the second-to-last item. An index outside the occupied range is a runtime error.

For methods that insert at an index, `index == length()` is valid and inserts at the end. An index greater than the collection's length is an error; insertion never creates gaps filled with `nil`.

Search methods return `nil` when no matching item or occurrence exists. `find_nth(item, number)` uses one-based occurrence numbering: `1` means the first occurrence, `2` the second, and so on. A `number` below `1` is a runtime error.

`copy()` performs a deep copy. Nested collections and structs are recursively copied. Repeated references and cycles preserve their topology: if two references in the original point to the same object, their copies point to the same copied object rather than two independent copies.

## Non-mutating conversion functions:
- `int int(any ?value)`
  - Converts `value` to an integer.
  - Returns `0` if omitted.
- `char char(any ?value)`
  - Converts `value` to a character.
  - Returns `'\0'` if omitted.
- `str str(any ?value)`
  - Converts `value` to a string.
  - Returns `""` if omitted.
- `float float(any ?value)`
  - Converts `value` to a floating-point number.
  - Returns `0.0` if omitted.
- `bool bool(any value)`
  - Converts `value` according to its truthiness.
- `list(T) list(type T, any ?value)`
  - Converts `value` into a list whose element type is `T`.
  - Returns `[]` if `value` is omitted.
  - Invocation syntax is `list(T, value)` or `list(T)`.
- `arr(T, N) arr(type T, any ?value, int ?capacity)`
  - Converts `value` into an array whose element type is `T`.
  - If `capacity` is omitted and `value` is provided, capacity defaults to the resulting length.
  - If both `value` and `capacity` are omitted, returns an empty array with capacity `0`.
  - If `capacity` is greater than the resulting length, the remaining capacity consists of internal empty slots. Empty slots are not Thorn `nil` values and cannot be read directly.
  - If `capacity` is smaller than the number of converted elements, excess elements are truncated and a warning is emitted.
  - Invocation syntax is `arr(T, value, capacity)`. `value` and `capacity` may also be named, so `arr(T, capacity = N)` creates an empty array with reserved capacity.
- `set(T) set(type T, any ?value)`
  - Converts `value` into a set whose element type is `T`.
  - Returns `()` if `value` is omitted.
  - Thorn sets are ordered, immutable collections and may contain duplicate values.
  - Invocation syntax is `set(T, value)` or `set(T)`.

These conversions always create a fresh outer collection and never mutate the source. A Thorn collection, string, or foreign Python iterable is copied in iteration order; a non-iterable Thorn value becomes one element. Elements are not individually coerced through primitive conversion functions: every produced element must already be compatible with `T`, otherwise conversion raises a source-positioned runtime error. Nested collection elements are checked recursively. Contained object identities are retained, so this is an outer-container copy rather than `copy()`'s recursive deep copy.

## Mutating conversion functions
- `nil to_int(any value)`
- `nil to_char(any value)`
- `nil to_str(any value)`
- `nil to_float(any value)`
- `nil to_bool(any value)`
- `nil to_list(any value)`
- `nil to_arr(any value, int ?capacity)`
  - Converts `value` into an array in place.
  - If `capacity` is omitted, capacity defaults to the resulting length.
  - If `capacity` exceeds the resulting length, the remaining capacity consists of internal empty slots.
  - If `capacity` is smaller than the resulting length, excess elements are truncated and a warning is emitted.

- `bool is_float(any value)`
- `bool is_bool(any value)`

## Integer methods:
- `bool gt(int value)`
  - Returns whether the integer is greater than `value`.
- `bool lt(int value)`
  - Returns whether the integer is less than `value`.
- `bool between(any lower, any upper)`
  - Returns whether the integer is between two values. If a boundary is provided as an integer, that boundary is inclusive; if it is provided as a string, that boundary is exclusive.
    ```
    5.between(1, 6) = [1, 6] = 1 ≤ 5 ≤ 6
    5.between("1", 6) = (1, 6] = 1 < 5 ≤ 6
    5.between(1, "6") = [1, 6) = 1 ≤ 5 < 6
    5.between("1", "6") = (1, 6) = 1 < 5 < 6
    ```

## List methods
- `nil append(T item)`
  - Adds `item` to the end of the list.
- `nil insert(T item, int index)`
  - Adds `item` at `index` and shifts the item previously at that index and all following items one position forward.
  - `index == length()` inserts at the end.
  - An index outside the valid insertion range is an error.
- `nil prepend(T item)`
  - Adds `item` at the beginning of the list and shifts all existing items one position forward.
- `T replace_at(T item, int index)`
  - Replaces the item at `index` with `item`.
  - Returns the previous item.
- `list(T) shorten(int amount = 1)`
  - Removes `amount` items from the end of the list.
  - Returns the removed items in their original order.
- `T remove_at(int index)`
  - Removes the item at `index` and shifts all following items one position backward.
  - Returns the removed item.
- `list(T) shave(int amount = 1)`
  - Removes `amount` items from the beginning of the list.
  - Shifts the remaining items backward and returns the removed items in their original order.
- `int length()`
  - Returns the number of items in the list.
- `int | nil find_first(any item)`
  - Returns the index of the first occurrence of `item`.
  - Returns `nil` if no occurrence exists.
- `int | nil find_nth(any item, int number)`
  - Returns the index of the specified occurrence of `item`.
  - `number` is one-based.
  - Returns `nil` if that occurrence does not exist.
  - A `number` below `1` is an error.
- `int | nil find_last(any item)`
  - Returns the index of the last occurrence of `item`.
  - Returns `nil` if no occurrence exists.
- `T locate(int index)`
  - Returns the item at `index`.
  - Negative indexes count backwards from the end.
- `nil compress()`
  - Removes all actual `nil` values from the list while preserving the order of all remaining items.
  - On a list whose element type cannot contain `nil`, this is normally a no-op.
    ```
    [1, 2, 3, nil, 4, nil, 5]
    ↓
    [1, 2, 3, 4, 5]
    ```
- `list(T) copy()`
  - Returns a deep copy of the list.

For both `shorten(amount)` and `shave(amount)`:
- `amount == 0` returns an empty list and does not modify the collection.
- `amount < 0` is an error.
- `amount > length()` is an error.

## Array methods
Arrays have both a **length** and a **capacity**.

- **length** is the number of occupied elements.
- **capacity** is the number of elements the array can contain before explicit resizing is required.
- Capacity is runtime allocation and is not part of static type identity.
- Unoccupied capacity consists of internal empty slots. Empty slots are not Thorn `nil` values and cannot be accessed as elements.
- Arrays never resize automatically. Operations that would exceed capacity produce a runtime error unless capacity is explicitly increased first.
- Capacity changes are visible through every alias referring to the same array.
- Assigning an existing array to a declaration written with a different `N` does not resize it.

Methods that access, replace, or remove existing items require an occupied index. An index below the array's capacity may still be invalid when it refers to an empty slot.

- `nil resize(int new_size)`
  - Explicitly changes the array's capacity.
  - `new_size < 0` is an error.
  - `new_size == capacity()` does nothing.
  - Increasing capacity creates additional internal empty slots and does not change length.
  - Reducing capacity below the current length truncates elements from the end until `length() <= new_size` and emits a runtime warning.
  - Resizing to `0` is valid; any occupied elements are truncated with a warning.
- `int length()`
  - Returns the number of occupied elements in the array.
- `int capacity()`
  - Returns the current runtime capacity of the array.
- `nil append(T item)`
  - Adds `item` to the end of the occupied portion of the array.
  - Raises an error if the array is full.
- `nil insert(T item, int index)`
  - Adds `item` at `index` and shifts the item previously at that index and all following occupied items one position forward.
  - `index == length()` inserts at the end.
  - Raises an error if the array is full.
  - An index greater than the current length is an error.
- `nil prepend(T item)`
  - Adds `item` to the beginning of the array and shifts all occupied items one position forward.
  - Raises an error if the array is full.
- `T replace_at(T item, int index)`
  - Replaces the occupied item at `index` with `item`.
  - Returns the previous item.
  - Does not change length or capacity.
- `list(T) shorten(int amount = 1)`
  - Removes `amount` occupied items from the end of the array.
  - Returns the removed items as a list in their original order.
  - Does not change array capacity.
- `T remove_at(int index)`
  - Removes the occupied item at `index`, shifts all following occupied items one position backward, and leaves an empty slot at the end of the occupied portion.
  - Returns the removed item.
  - Does not change capacity.
- `list(T) shave(int amount = 1)`
  - Removes `amount` occupied items from the beginning of the array.
  - Shifts the remaining occupied items backward and returns the removed items as a list in their original order.
  - Does not change array capacity.
- `int | nil find_first(any item)`
  - Returns the index of the first occurrence of `item`.
  - Returns `nil` if no occurrence exists.
- `int | nil find_nth(any item, int number)`
  - Returns the index of the specified occurrence of `item`.
  - `number` is one-based.
  - Returns `nil` if that occurrence does not exist.
  - A `number` below `1` is an error.
- `int | nil find_last(any item)`
  - Returns the index of the last occurrence of `item`.
  - Returns `nil` if no occurrence exists.
- `T locate(int index)`
  - Returns the occupied item at `index`.
  - Negative indexes count backwards from the end of the occupied elements, not from capacity.
- `nil compress()`
  - Removes all actual `nil` values from the occupied portion of the array and shifts the remaining elements together while preserving their order.
  - Capacity remains unchanged.
  - Internal empty slots are not Thorn `nil` and are unaffected.
  - On an array whose element type cannot contain `nil`, this is normally a no-op.
    ```
    <1, 2, 3, nil, 4, nil, 5>
    ↓
    <1, 2, 3, 4, 5>
    ```
- `arr(T, N) copy()`
  - Returns a deep copy of the array.
  - The copied array initially has the same current capacity as the source array.
- `nil fill(T value)`
  - Fills every currently unoccupied slot with `value`.
  - Existing occupied elements are not replaced.
  - After the operation, `length() == capacity()`.
  - If the array is already full, the operation does nothing.
    ```
    arr(int, 5) array = <1, 2, 3>
    array.fill(1)

    >> <1, 2, 3, 1, 1>
    ```
  - A value incompatible with `T` is a type error.
- `nil skintight()`
  - Reduces capacity until it equals length.
  - Emits the warning: `warning: using internal name "skintight". Consider "shrink_to_fit()" instead, weirdo`.
- `nil shrink_to_fit()`
  - Reduces capacity until it equals length without emitting the `skintight()` warning.

For both `shorten(amount)` and `shave(amount)`:
- `amount == 0` returns an empty list and does not modify the array.
- `amount < 0` is an error.
- `amount > length()` is an error.

Slicing an array produces a new array containing the selected occupied elements. The resulting array's capacity is exactly equal to its resulting length.

## Set methods
Thorn sets are ordered, immutable collections. Unlike mathematical sets and sets in many other languages, Thorn sets permit duplicate values and retain their order. Their contents cannot be added to, removed from, replaced, or reordered after construction.

A non-`const` variable containing a set may still be rebound to another set. `const set(T)` prevents that rebinding as well.

- `int length()`
  - Returns the number of items in the set.
- `int | nil find_first(any item)`
  - Returns the index of the first occurrence of `item`.
  - Returns `nil` if no occurrence exists.
- `int | nil find_nth(any item, int number)`
  - Returns the index of the specified occurrence of `item`.
  - `number` is one-based.
  - Returns `nil` if that occurrence does not exist.
  - A `number` below `1` is an error.
- `int | nil find_last(any item)`
  - Returns the index of the last occurrence of `item`.
  - Returns `nil` if no occurrence exists.
- `T locate(int index)`
  - Returns the item at `index`.
  - Negative indexes count backwards from the end.
- `set(T) copy()`
  - Returns a deep copy of the set.

## Functional
- `int index(any item)`
  - Extracts the index attached to an item obtained through a `foreach`.
- `str input(str ?preview)`
  - Prints the optional `preview`, then returns the contents read from standard input.
- `nil print(any output, str end = "\n")`
  - Prints `output`.
  - `end` is appended after the output and defaults to a newline.

## File handling

- `File open(str path, str mode = "r", str encoding = "utf-8")`
  - Opens a text file. Supported modes are `r`, `w`, `a`, `x`, and their `+` variants.
  - Binary modes are unavailable until Thorn has a `bytes` type.
- `str File.read(int | nil size = nil)`
  - Reads the rest of the file, or at most `size` characters when supplied.
- `str File.readline(int | nil size = nil)`
  - Reads one line, optionally limited to `size` characters. A retained line terminator is part of the returned string.
- `list(str) File.readlines()`
  - Reads all remaining lines, retaining their line terminators.
- `int File.write(str content)`
  - Writes `content` at the current position and returns the number of characters accepted.
- `nil File.writelines(list(str) lines)`
  - Writes each string exactly as supplied. Newline characters are not added automatically.
- `nil File.flush()`
  - Flushes buffered output to the underlying stream.
- `int File.seek(int offset, int origin = 0)`
  - Moves the stream position. `origin` uses Python-compatible values: `0` for the beginning, `1` for the current position, and `2` for the end, subject to text-stream restrictions.
- `int File.tell()`
  - Returns an opaque text-stream position suitable for passing back to `seek()`.
- `nil File.close()`
  - Flushes and closes the file. Calling `close()` on an already closed file does nothing.
- `bool File.closed()`
  - Returns whether the file is closed.
- `bool File.readable()`
  - Returns whether the selected mode permits reading.
- `bool File.writable()`
  - Returns whether the selected mode permits writing.
- `bool File.seekable()`
  - Returns whether the underlying stream supports seeking.

File and encoding failures are reported as source-positioned Thorn runtime errors.

## Python interoperability
- `pyobject pyimport(str module)`
  - Imports `module` using Python's normal import system and returns the module as a foreign object.
  - Runic form: `ᛈᛠᚪᛒᚷᚻᛖᚳᛏ ᛈᛠᛁᛗᛈᛟᚱᛏ(ᛋᛏᚱ ᛗᚫᚷᚻᚣᛚ)`.
- `import python "module" as binding;`
  - Imports the Python module and declares `binding` with static type `pyobject`.
  - Equivalent to `pyobject binding = pyimport("module");`.

Operations supported by `pyobject` values:
- `object.member`: dynamically retrieves a Python attribute and returns it as `pyobject`.
- `object(arguments...)`: invokes a wrapped Python callable. Thorn named arguments become Python keyword arguments.
- `object[index]`: performs Python indexing and returns `pyobject`.
- `object[start:end]`: performs Python slicing and returns `pyobject`.
- `foreach (item in object)`: iterates a Python iterable; each item has static type `pyobject`.

Python return values remain `pyobject` even when their runtime value is a Python primitive. Explicit Thorn conversion establishes a statically known Thorn type.
